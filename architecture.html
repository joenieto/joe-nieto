Architecture

How these apps are built

Joe describes an app in plain language, an assistant writes the code, and Joe reviews the change before it goes on the web. When someone opens it, the app already knows where its data lives and which model, if any, it should call.

  1. 1

    Joe describes it

    He says what he wants in plain language to Grok, Grok Bot, or Claude in Cursor's cloud coding agents. The assistant writes the code.

  2. 2

    He reviews the change

    GitHub or Cursor Origin keeps the code. The change arrives as a pull request. Joe reviews it and merges it.

  3. 3

    Vercel publishes it

    Vercel builds the app and serves it at an address ending in vercel.app. Three video demos open on Tavus.

  4. 4

    Data has a home

    Turso (libSQL) stores Ideation Dashboard sessions and Post-Discharge Voice calls. Other apps keep data in the browser, on the device, or in a sample file shipped with the app.

  5. 5

    A model may answer

    Google Gemini reads knee X-rays. Sakana Fugu researches an NPS score. The list below names the voice service, document reader, or on-device work for every app.

  6. 6

    Someone opens it

    A person uses the app in a browser, on a phone or a computer.
